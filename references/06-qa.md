# Stages 6–7: QA and Fix

The current Codex session owns each QA cycle. A cycle checks every route and viewport in order, then applies fixes only after the user approves the QA report.

## Stage 6: QA

### Inputs

- Running clone in OUTPUT_DIR and its local development server
- 03-design-spec/DESIGN.md
- 03-design-spec/assertions.json
- 01-recon/sitemap.json and the viewport list in 00-config.json

### Procedure

1. Start the local development server if it is not already running. Confirm localhost responds before collecting values.
2. For each route and viewport, use the configured browser-control tool to open the clone, set the exact viewport, wait for hydration and fonts, and disable animation when possible.
3. For every assertion that applies to that route and viewport, read the property with getComputedStyle. Store readings under route, viewport, selector, and property in 06-qa/cycle-{N}/clone-styles.json. Example:

~~~json
{
  "/": {
    "desktop": {
      ".hero-title": { "fontSize": "64px", "fontWeight": "800" }
    }
  }
}
~~~

4. Capture a screenshot for visual review when available. It is not a gate input; save a path only if the browser tool returns an actual file.
5. Replay each reachable interaction from `01-recon/interaction-map.json` on the clone. Record whether the expected state appears and behaves; list omissions in `bugs.json` or `progress.md`, separate from style assertion results.
6. Run the comparison from `clone-workspace/{name}/`, replacing `<skill-dir>` with the directory containing `SKILL.md`:

~~~bash
node "<skill-dir>/scripts/assert-styles.mjs" \
  --assertions 03-design-spec/assertions.json \
  --clone-styles 06-qa/cycle-{N}/clone-styles.json \
  --out 06-qa/cycle-{N}/metrics.json
~~~

The script exits nonzero when assertions fail. Read the failures from metrics.json; do not treat a nonzero exit as a tool crash.
7. Run npm run build from OUTPUT_DIR. Record its result in progress.md.
8. Write 06-qa/cycle-{N}/bugs.json as an array of measured failures. Each entry includes page, viewport, selector, expected, actual, evidence_method, fix_hint, and file. Use the assertion’s expected/actual values and the component map to identify a likely source file. If there are no failures, write an empty array.
9. Update status.json. Report the assertion count, build result, interaction review, artifact paths, and any blocker. Stop and wait for user approval before starting Stage 7 or another cycle.

A QA cycle passes only when style_assertions.failed is zero and npm run build exits successfully. Review screenshots for missing sections or broken composition, but do not claim that visual review is a measured pass.

If an authenticated route is unavailable, or the clone is blank or redirects to login, record the route and reason as blocked. Do not score the login screen as the clone.

## Stage 7: Fix

After the user approves the QA report:

1. Sort bugs by impact and select one measured issue.
2. Inspect the named source file and make the smallest change that moves the computed value toward the expected token.
3. Reopen the same route at the same viewport, read the affected computed style, and rerun assert-styles.mjs.
4. Keep the change only if it improves the target without regressing another assertion. Revert an ineffective or regressive edit.
5. Run npm run build before finishing the fix stage.
6. Update progress.md and status.json with changed files and measured results. Report the summary and exact paths, then wait for user approval before the next QA cycle.

Do not split work into parallel fix sets. One writer avoids conflicting edits and keeps each change easy to measure.

## Evidence rules

- Each bug must name the measured property and actual value and compare it with the expected value.
- Use getComputedStyle, CSSOM, a driven interaction state, or an assert-styles.mjs failure as evidence_method.
- Never report “looks off” as a measured finding.
- If a selector is absent, record actual as null and explain the absence.
- Use route and viewport scopes for assertions whose values vary by page or responsive layout.
